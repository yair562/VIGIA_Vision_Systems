4. Principio de Trabajo Paralelo

La presencia de una actividad en un periodo no significa que las demás actividades deban esperar.

Las dependencias serán administradas mediante:

- Contratos.
- Interfaces.
- APIs.
- Protocolos.
- Datos simulados.
- Mocks.
- Stubs.
- Simuladores.
- Hardware de prueba.
- Fixtures.
- Pruebas automatizadas.

Ejemplo de desacoplamiento

Frontend
   │
   └──► Mock API
            │
            ▼
        Dashboard

Mientras Backend desarrolla:

Backend
   │
   └──► API real

Posteriormente:

Mock API
    ↓
API real
    ↓
Integración

El mismo principio aplica a IA, Hardware, Data y demás dominios.

7. Regla de Protección del Deadline

El 16 de diciembre de 2026 es el deadline absoluto.

06 de diciembre — Release Candidate

El sistema debe ser esencialmente funcional.

07–13 de diciembre — Estabilización

Se priorizan:

- Bugs.
- Integración.
- Pruebas.
- Documentación.
- Evidencias.
- Preparación de demo.

13 de diciembre — Feature Freeze

No se incorporan funcionalidades nuevas salvo situaciones críticas.

14–16 de diciembre — Cierre y Entrega

No se planifica desarrollo ordinario.

Se realiza:

- Empaquetado.
- Revisión.
- Backup.
- Instalación final.
- Validación.
- Presentación.
- Entrega.
